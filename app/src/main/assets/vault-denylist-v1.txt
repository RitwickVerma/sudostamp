# SudoStamp vault-grant denylist, version 1 (docs/design/vault-grant.md section 5).
#
# Hosts no grant may touch. Built in, and the owner cannot remove these rules; the owner can only
# add hosts on the phone. The login service imports this same file and the vectors in
# app/src/test/resources/vault/denylist-vectors.txt, and asserts the two sides agree.
#
# Syntax: one rule per line, exactly `kind:value`, LF line endings, no spaces, no inline comments.
#   host:x      x and every subdomain of x (h == x, or h ends with "." + x)
#   suffix:x    the same, but x may be a single label (a zone such as gov)
#   label:x     any label of the host equal to x
#   contains:x  any label of the host containing x
# Values are lowercase LDH. A malformed line fails the whole file (Denylist.parseRules).
#
# Too broad is the safe direction: a denied host costs the owner a manual share in the Bitwarden
# app, an allowed one can hand an agent a mailbox or a bank.
